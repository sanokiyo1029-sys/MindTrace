The system

The teacher works on a laptop; the phone only takes photos. Everything runs on one PC: the frontend on port 5173, the API on 8000, and a tunnel that gives the phone an HTTPS address.

  1. 1Frontend ↔ backendEvery call is /api/… with the JSON shapes and snake_case names in docs/CONTRACTS.md. Errors are always {error, message}.
  2. 2Backend ↔ AI moduleOne Python import of four pure functions. ai_bridge.py falls back to built-in samples if the module is missing or fails, and re-checks every answer key. /api/health reports ai_module_loaded.
  3. 3Shared fixturesSample JSON for every shape. The frontend's mock mode, the AI's offline mode and the demo roster all read tests/fixtures/.
  4. 4Sheet layoutPositions in mm from the top-left of A4. The PDF and the scanner both read this one file, so changing it means reprinting the test pack.
  5. 5One .envAt the repo root. The backend and Vite both read it; it is never committed. .env.example lists the names.

Inside a scan

What POST …/scans does with one phone photo. Nothing is guessed: a sheet that can't be identified is rejected with a reason, and an answer that isn't one clear mark goes to the teacher with its crop.
